# Porto

The `/` route is the Voyager homepage. `app/page.tsx` fetches live content from Porto Service and renders `components/voyager/page-layout.tsx` with React sections for Projects, Experience, Achievements, Journal, and Contact. The Voyager stylesheet is bundled from `components/voyager/voyager.css` through `app/globals.css`; section content and controls use Tailwind classes in their React components. The remaining CSS covers the scene, scroll choreography, responsive stage geometry, and image travel. Animation scripts remain in `public/voyager`; media lives in `public/models`, `public/vendor`, and `public/assets`. Journal detail is a React-controlled full-screen dialog. The old standalone experience route has been removed.

Start Porto Service, apply migrations, and run its demo seed if you want the current section examples. Set `NEXT_PUBLIC_API_BASE_URL` in `.env.local` to the service base URL, such as `http://127.0.0.1:3100/api/v1`, then run `npm run dev`. The homepage reads `/content/section-content`. Production builds require the same environment variable pointing at the deployed service. If the API is unavailable, the page shows a content error.

Edit homepage section copy in Porto Control → Settings → Site Config. Projects and skills marked **Show on portfolio** appear on the homepage. Work Experience forms the timeline, Education provides the third chapter subtitle, and Certification and Award records form the scrolling achievement cards. Settings controls the name, bio, location, portrait, contact links, and CV. Uploaded media and the CV are delivered through same-origin Porto routes to avoid mixed content in an HTTPS deployment.

Edit the Voyager files in this repository directly. The homepage does not need a separate asset sync step. The page credits identify the 3D model and gallery sources.
